🎨 Claude Code 완벽 가이드

초등학생도 5분만에 이해하는 바이브코딩!

🤖 자동으로 작동

  • Rules (룰) - 항상 지켜지는 규칙
  • Hooks (훅스) - 특정 상황에 자동 실행
  • 따로 명령할 필요 없어요!
  • 배경에서 조용히 일해요

⌨️ 슬래시(/)로 실행

  • Commands (커맨드) - /plan, /tdd 등
  • Skills (스킬) - 필요할 때 호출
  • Agents (에이전트) - 자동으로 불러짐
  • 내가 원할 때만 사용해요
📜

Rules (룰)

항상 자동으로 지켜지는 8가지 규칙 🤖 자동 실행
🔒
security.md
보안 규칙 - 비밀번호나 중요한 정보를 코드에 넣지 않아요
📌 예시:
"비밀번호는 절대 코드에 직접 쓰지 마세요!"
✨
coding-style.md
코딩 스타일 - 코드를 깔끔하고 읽기 쉽게 써요
📌 예시:
"함수는 50줄 이내로, 파일은 정리정돈!"
🧪
testing.md
테스트 규칙 - 만든 코드는 꼭 테스트해봐요
📌 예시:
"코드의 80%는 테스트를 통과해야 해요"
📝
git-workflow.md
Git 규칙 - 코드 저장하는 방법
📌 예시:
"커밋 메시지는 '무엇을 왜 바꿨는지' 명확하게"
👥
agents.md
에이전트 사용 규칙 - 언제 전문가를 부를지 결정
📌 예시:
"복잡한 일은 전문 에이전트한테 맡기기"
🎨
patterns.md
패턴 규칙 - 반복되는 코드 작성법
📌 예시:
"API 응답은 항상 같은 형식으로"
⚡
performance.md
성능 규칙 - 빠르고 효율적으로 작동하게
📌 예시:
"간단한 일은 Haiku, 복잡한 일은 Opus 모델 사용"
🪝
hooks.md
훅스 규칙 - 자동화 설정 방법
📌 예시:
"파일 저장하면 자동으로 포맷팅하기"
⚡

Commands (커맨드)

슬래시(/)로 실행하는 23개의 빠른 명령어 ⌨️ /명령어
📋
/plan
계획 세우기 - 무언가 만들기 전에 단계별로 계획
📌 사용법:
"/plan 할일 목록 앱 만들기"
🧪
/tdd
테스트 먼저 만들기 - 테스트를 먼저 만들고 코드 작성
📌 사용법:
"/tdd 로그인 기능 테스트"
🎭
/e2e
실제 사용 테스트 - 사용자처럼 직접 사용해보는 테스트
📌 사용법:
"/e2e 버튼 클릭했을 때 작동 확인"
🔍
/code-review
코드 검사하기 - 코드에 문제가 없는지 확인
📌 사용법:
"/code-review 내 코드 검사해줘"
🔧
/build-fix
에러 고치기 - 빨간 에러 메시지가 뜰 때 사용
📌 사용법:
"/build-fix 에러 자동으로 고쳐줘"
🧹
/refactor-clean
청소하기 - 쓸모없는 코드와 파일 정리
📌 사용법:
"/refactor-clean 안 쓰는 파일 지워줘"
📚
/learn
배우기 - 작업하면서 새로운 패턴 학습
📌 사용법:
"/learn 이번 세션에서 뭘 배웠는지 정리"
✅
/verify
검증하기 - 모든 게 제대로 작동하는지 확인
📌 사용법:
"/verify 전체 시스템 확인해줘"
📊
/test-coverage
테스트 범위 - 얼마나 테스트했는지 확인
📌 사용법:
"/test-coverage 테스트 얼마나 했어?"
📝
/update-docs
문서 업데이트 - 설명서를 최신으로 유지
📌 사용법:
"/update-docs README 최신으로 바꿔줘"
💾
/checkpoint
체크포인트 - 현재 상태 저장하기
📌 사용법:
"/checkpoint 지금 상태 저장"
🐹
/go-test
Go 테스트 - Go 언어 전용 테스트
📌 사용법:
"/go-test Go 코드 테스트해줘"
🐹
/go-build
Go 빌드 - Go 언어 빌드 문제 해결
📌 사용법:
"/go-build Go 빌드 에러 고쳐줘"
🐹
/go-review
Go 리뷰 - Go 코드 품질 검사
📌 사용법:
"/go-review Go 코드 검사해줘"
🎯
/orchestrate
총괄 관리 - 여러 작업을 한번에 조율
📌 사용법:
"/orchestrate 모든 작업 관리해줘"
📊
/eval
평가하기 - 작업 품질 평가
📌 사용법:
"/eval 이번 작업 평가해줘"
🧬
/evolve
진화하기 - 학습한 내용을 적용
📌 사용법:
"/evolve 배운 패턴 적용하기"
💡
/skill-create
스킬 만들기 - 새로운 스킬 생성
📌 사용법:
"/skill-create 내 작업을 스킬로 만들어줘"
🗺️
/update-codemaps
코드맵 업데이트 - 코드 구조도 최신화
📌 사용법:
"/update-codemaps 프로젝트 구조 업데이트"
📦
/setup-pm
패키지 매니저 설정 - npm, yarn 등 설정
📌 사용법:
"/setup-pm npm으로 설정해줘"
📤
/instinct-export
본능 내보내기 - 학습한 패턴 저장
📌 사용법:
"/instinct-export 학습 데이터 저장"
📥
/instinct-import
본능 가져오기 - 저장된 패턴 불러오기
📌 사용법:
"/instinct-import 이전 학습 불러오기"
📊
/instinct-status
본능 상태 - 학습 진행 상황 확인
📌 사용법:
"/instinct-status 뭘 배웠는지 보여줘"
👨‍🍳

Agents (에이전트)

12명의 전문가 요리사 - 필요할 때 자동으로 불려나와요 🤖 자동 호출
📐
architect
건축가 - 시스템 구조를 설계해요
📌 언제 나올까:
"이 앱 구조를 어떻게 만들지?" → 건축가 등장!
📋
planner
기획자 - 단계별 계획을 세워요
📌 언제 나올까:
"/plan" 명령어 쓰면 → 기획자가 계획서 작성!
🧪
tdd-guide
테스트 선생님 - 테스트 먼저 만드는 법 알려줘요
📌 언제 나올까:
"/tdd" 명령어 → 테스트 선생님이 가이드!
🔍
code-reviewer
코드 검사관 - 코드 품질을 검사해요
📌 언제 나올까:
"/code-review" → 검사관이 꼼꼼히 확인!
🛡️
security-reviewer
보안 경비원 - 보안 문제를 찾아내요
📌 언제 나올까:
보안 검사 필요할 때 → 경비원이 취약점 체크!
🔧
build-error-resolver
수리공 - 빌드 에러를 고쳐요
📌 언제 나올까:
"/build-fix" → 수리공이 에러 고침!
🎭
e2e-runner
배우 - 실제 사용자처럼 테스트해요
📌 언제 나올까:
"/e2e" → 배우가 직접 버튼 눌러보고 테스트!
🧹
refactor-cleaner
청소부 - 쓸모없는 코드를 지워요
📌 언제 나올까:
"/refactor-clean" → 청소부가 깨끗이 정리!
📝
doc-updater
기록담당 - 문서를 최신으로 유지해요
📌 언제 나올까:
"/update-docs" → 기록담당이 문서 업데이트!
🐹
go-reviewer
Go 전문가 - Go 언어 코드를 검사해요
📌 언제 나올까:
"/go-review" → Go 전문가가 코드 리뷰!
🐹
go-build-resolver
Go 수리공 - Go 빌드 문제를 해결해요
📌 언제 나올까:
"/go-build" → Go 수리공이 문제 해결!
💾
database-reviewer
데이터베이스 전문가 - DB 구조를 검토해요
📌 언제 나올까:
데이터베이스 작업 시 → DB 전문가가 최적화!

Skills (스킬)

16가지 전문 기술 레시피북 - 특정 상황에서 사용해요 ⌨️ 자동 활용
🎨
frontend-patterns
프론트엔드 패턴 - 웹 화면 만드는 법
📌 무엇을:
React, Next.js로 예쁜 화면 만드는 모범 사례
⚙️
backend-patterns
백엔드 패턴 - 서버 만드는 법
📌 무엇을:
API, 데이터베이스, 캐싱 같은 서버 기술
✨
coding-standards
코딩 표준 - 언어별 좋은 코드 작성법
📌 무엇을:
JavaScript, Python, Go 등 각 언어의 베스트 프랙티스
🧪
tdd-workflow
TDD 워크플로우 - 테스트 먼저 만드는 방법
📌 무엇을:
테스트 → 코드 → 개선 순서로 개발하기
🛡️
security-review
보안 리뷰 - 보안 체크리스트
📌 무엇을:
XSS, SQL 인젝션 같은 보안 위협 확인
🧠
continuous-learning
지속 학습 - 작업하면서 패턴 배우기
📌 무엇을:
반복되는 패턴을 자동으로 학습하고 저장
🧠
continuous-learning-v2
지속 학습 v2 - 더 똑똑한 학습
📌 무엇을:
신뢰도 점수로 더 정확하게 패턴 학습
🔍
iterative-retrieval
반복 검색 - 점진적으로 필요한 정보 찾기
📌 무엇을:
큰 프로젝트에서 필요한 부분만 찾아서 작업
📦
strategic-compact
전략적 압축 - 대화 내용 정리하기
📌 무엇을:
긴 대화를 중요한 부분만 남기고 압축
✅
verification-loop
검증 루프 - 계속 확인하면서 작업
📌 무엇을:
만들고 → 테스트 → 고치고 반복
📊
eval-harness
평가 도구 - 작업 품질 측정
📌 무엇을:
만든 것이 요구사항을 충족하는지 평가
🐹
golang-patterns
Go 패턴 - Go 언어 관용구와 모범 사례
📌 무엇을:
Go 언어를 효율적으로 쓰는 방법
🐹
golang-testing
Go 테스팅 - Go 테스트와 벤치마크
📌 무엇을:
Go 언어로 테스트 작성하고 성능 측정
🐘
postgres-patterns
PostgreSQL 패턴 - 데이터베이스 최적화
📌 무엇을:
PostgreSQL을 빠르고 효율적으로 사용
📊
clickhouse-io
ClickHouse 사용법 - 빅데이터 처리
📌 무엇을:
대용량 데이터를 빠르게 분석하는 방법
📋
project-guidelines-example
프로젝트 가이드라인 - 프로젝트별 규칙 예시
📌 무엇을:
우리 프로젝트만의 특별한 규칙 만들기

실제 사용 흐름 - 예시로 배우기

📱 "할일 목록 앱 만들기" 전체 과정

⌨️ 당신: "/plan 할일 목록 앱 만들기"

2

📋 planner: "계획을 세웠어요!"

1) HTML 구조 만들기 2) CSS 디자인 3) JavaScript 기능 4) 테스트하기

3

🤖 Claude가 코드 작성 시작

Rules가 자동 작동: security.md(보안 체크), coding-style.md(깔끔한 코드), testing.md(테스트 필수)

4

✨ frontend-patterns 스킬 자동 활용

웹 화면 만들 때 프론트엔드 패턴 레시피북을 자동으로 참고

5

⌨️ 당신: "/tdd 할일 추가 기능"

tdd-guide 에이전트 등장 → 테스트 먼저 만들고 코드 작성

6

⌨️ 당신: "/e2e 버튼 클릭 테스트"

e2e-runner 에이전트 등장 → 실제로 버튼 눌러보고 작동 확인

7

⌨️ 당신: "/code-review"

code-reviewer 에이전트 + security-reviewer 에이전트 등장 → 코드 품질과 보안 검사
