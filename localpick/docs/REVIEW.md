# LocalPick Korea — 기획·경쟁 서비스·코드 검토

검토일: 2026-10-02 (한국 시간). 대상: [원본 PR #1](https://github.com/dudqks0319-cpu/-/pull/1)의 `localpick/`. 기존 근무표와 다른 여행 앱은 대상에서 제외했다.

## 판단

현재는 한국의 지역·음식·쇼핑을 찾고 한국어로 주문을 보여주는 정적 가이드다. 기능 범위가 작은 첫 검토판으로 적합하다. 실제 여행 서비스로 공개하기 전 가장 먼저 보완할 것은 **장소 정보의 신뢰성**과 **저장 후 다시 찾아오는 흐름**이다. 예약·결제·리뷰 플랫폼까지 한꺼번에 확대할 필요는 없다.

계획 문서는 README와 PR 설명뿐이며, 별도의 요구사항·정보 검증 기준·성공 지표·테스트 계획은 없었다. 현재 자료는 4개 도시, 49개 장소, 51개 메뉴, 24개 쇼핑 항목, 한국어·영어·일본어로 구성돼 있다. 장소는 샘플이며 지도 좌표는 대략값이다. 실제 장소 사진은 없다. 문구·번역·약국 상품 추천은 콘텐츠 검수 전 상태다.

## 경쟁 서비스 비교

공식 기능 소개를 비교했다. 각 서비스 앱을 실제 기기에 설치해 비교한 결과는 아니다.

차별점 후보는 **검증한 동네 장소 → 방문에 필요한 한국어 → 메뉴 읽기 → 직원에게 주문 보여주기**를 짧게 이어주는 흐름이다. '현지인이 많이 간다'는 표현에는 실제 확인 근거가 필요하다. 경쟁사의 기능 목록을 모두 복제하는 방식은 권하지 않는다.

## 코드 검토 결과

| 중요도 | 확인 내용 | 조치·남은 일 |
|---|---|---|
| 높음 | `data.js`의 `locals`, `tourists` 숫자에 출처·집계 기준이 없는데 `meter()`가 인기도처럼 표시 | 이번 검토판에서는 숫자/등급을 숨기고 미확인 상태 표시. 검증 후 데이터로 복구 |
| 높음 | 샘플과 대략 좌표라는 설명이 README에만 있고 홈은 확정적인 추천 문구 | 모든 화면에 샘플 안내, 장소마다 미확인 표시, 과장된 비교 문구 수정 |
| 높음 | OCR 초기 코드에 파일 크기 제한·취소·시간 제한·동시 작업 결과 분리가 없음 | Claude에 수정 요청. 최종 커밋 및 로컬 검증은 CURRENT_STATE 참고 |
| 높음 | OCR 오독이나 부분 일치를 실제 메뉴로 혼동할 수 있음. 일반 식재료 태그는 알레르기 검증 자료가 아님 | 원본 메뉴 및 직원 확인 안내. 식사 안전 보증으로 사용하지 않음 |
| 중간 | `Translator` 존재 확인만으로 모든 기기에서 번역된다고 볼 수 없음 | [Chrome 공식 문서](https://developer.chrome.com/docs/ai/translator-api?hl=en)상 데스크톱 지원. 기기·언어 지원 확인 및 외부 번역 대체 경로 필요 |
| 중간 | 네이버 블로그 검색 URL을 구글 번역으로 감싼 링크가 항상 번역된다는 보장이 없음 | 검색 링크라는 점 표시. 네이버 지도 앱 방문자 후기 번역과 구분 |
| 중간 | 주문 상태가 메모리에만 있어 새로고침하면 사라짐. 장소 저장·일정 없음 | 다음 구현 우선순위. 브라우저 저장으로 시작할 수 있음 |
| 중간 | 대화상자 포커스 순환 제한이 없음. 터치 화면만으로 접근성 완료를 판단할 수 없음 | 키보드·스크린리더 검증 및 포커스 관리 보완 필요 |
| 중간 | `index.html`에 스타일·문구·화면·OCR가 집중. 테스트 실행 환경 명시가 부족 | 규모가 커질 때 언어/메뉴 처리/화면 분리. 이번에는 큰 재구성 생략 |

양호한 부분: 새 서버나 API 키가 없고, OCR 엔진·한국어 모델을 같은 사이트에서 제공한다. 사용자가 입력한 검색어와 OCR 글자는 HTML 출력 전에 이스케이프한다. 언어 저장은 예외 처리되어 있다. 지도 타일 실패 상태와 이미지 없는 카드 대체 화면이 있다. 외부 링크에는 `noopener`가 있다.

## 백엔드 판단과 확장 설계

### 현재: 정적 Sites로 충분

- 장소·메뉴 읽기·주문 카드: 정적 파일 + 브라우저 메모리.
- 사진 글자 읽기: Tesseract.js를 기기에서 실행. 사진 원본의 서버 업로드 불필요.
- 저장한 장소·개인 일정 1차 버전: 브라우저 저장소로 구현 가능. 삭제/다른 기기 복원 한계는 화면에 표시.
- 기본 외부 요청: 폰트, 지도 타일, 사용자가 누른 지도·번역 링크. '사진을 업로드하지 않음'과 '외부 통신 없음'은 다르다.

### 서버가 필요한 시점

| 요구 | 저장 구조·API 초안 | 반드시 지킬 경계 |
|---|---|---|
| 여러 기기에서 저장·일정 복원 | `trips`, `trip_items`, `saved_places`; `/api/me/trips`, `/api/me/saved-places` | 인증 세션의 사용자 ID로 소유권 검사, 다른 사용자 ID 입력 거부 |
| 동행 공유·공동 편집 | `trip_members`; 보기/편집 권한, 만료·회수 가능한 초대 | 기본 비공개, 수정 버전 충돌 검사, 초대 재사용 정책 |
| 검증된 장소 CMS | `places`, `place_translations`, `source_urls`, `verified_at`, `verification_status`, `editor_notes` | 공개 읽기는 검증된 자료만, 관리자 쓰기는 명시된 역할만 |
| 사용자 제보·후기 | `reports`, `moderation_actions` | 입력 크기 제한, 스팸 방지, 검토 후 공개, 개인정보 최소 수집 |
| 사전에 없는 메뉴 자동 번역 | `/api/translate` 또는 지원되는 기기 번역 | 사진 업로드 동의, 텍스트 최소화, 인증·사용량 제한·전체 비용 상한·중복 차단·중지 스위치 |

실제 서버/DB는 아직 만들지 않았다. 현재 없는 계정·동행 공유 요구를 가정하여 운영 서비스나 비용을 켜지 않았다. 서버를 추가할 때 Sites의 현재 DB/인증 지원을 확인해 같은 사이트에 연결하며, 이 문서는 배포된 API 증거가 아니다.

## 다음 제품 범위 제안

1. 서울 한 동네부터 10곳을 실제 확인: 업소명·주소·좌표·영업시간·대표 메뉴·출처·확인일·사용 허가 사진.
2. 저장한 장소와 간단한 하루 일정: 새로고침 복원, 내보내기, 정확한 지도 연결.
3. 실제 iPhone·Android에서 사진 메뉴판, 느린 통신, 로밍 환경, 취소·재시도 검사.
4. 계정 복원/동행 공유가 필요해지면 위 서버 경계에 맞춰 추가.

## 출시 기준

비공개 검토판 배포와 일반 여행자 대상 공개는 구분한다. 샘플 장소를 실제 추천으로 바꾸려면 콘텐츠 검수, 실제 기기 카메라·OCR, 번역/지도 이동을 확인해야 한다. 알레르기·약국 제품 설명은 독립적인 원문 검증이 필요하다.

## 이번 검토에서 직접 확인한 브라우저 동작

- 한국어·영어·일본어 전환, 검색, 메뉴 수량·요청 선택 → 한국어 주문서.
- 모바일 390px 설정에서 홈·목록·주문서. 실제 콘텐츠 영역 375px, 가로 넘침 없음.
- 서울 지도 타일 9개 로딩과 핀 표시. 정확한 장소 좌표 검증과는 별개.
- 별도 테스트 메뉴 이미지의 5개 음식과 가격: 돼지국밥 9,000원, 비빔밥 10,000원, 김치찌개 8,000원, 삼겹살 16,000원, 공깃밥 1,000원을 실제 OCR 엔진으로 읽었다. 합성된 읽기 쉬운 테스트 자료이며 실제 식당 사진 정확도를 의미하지 않는다.
- 소스 검사 8항목 통과: 문법, 장소 참조·ID·좌표 범위, 메뉴 번역·중복, 쇼핑 수, 정적 자산 존재, 샘플 표시, 비밀값 패턴, 부분 일치 주문 차단.
- Tesseract.js 7.0.0의 두 JS 파일이 npm 공식 배포본과 바이트 단위로 일치. 빠진 번들 라이선스 고지 2개 보완.
- 실제 휴대폰 카메라·사진 회전·저사양 기기 메모리·사전 미등록 음식 인식률은 미확인.

## 최종 통합 검토

- Claude 최종 OCR 커밋: `4025fa15be85796606a699e664bf3cf613c4d7f4`.
- Codex 최종 동작 수정: `11264272fbefcaccdad23fef5ef0c329cb3342dc`.
- 부분 일치 결과에 주문 버튼이 남아 다른 음식으로 주문되는 문제를 발견해 수정했다. 예: 돼지갈비찜 → 돼지갈비 참고 설명에는 수량 버튼을 제공하지 않는다. 정확 일치 메뉴의 주문 버튼은 유지한다.
- 통합본 브라우저에서 정확 일치 5개/가격 5개, 부분 일치 경고 1개와 주문 버튼 없음, 비사진·손상 사진 오류, 읽기 중 취소와 재시도를 직접 확인했다.
- Claude가 제공한 `ocr-check.js`는 결과 수집용 smoke script다. 의미 검증 assertion이 없으므로 종료 코드 0만으로 모든 시나리오가 자동 통과했다고 해석하면 안 된다. Claude의 6000×8000/41MB/60초 시간 초과 검증 보고와 Codex 직접 확인을 구분한다.
- 60초 제한은 엔진 초기 로딩에 적용된다. 인식 시간 전체 제한은 없으며 사용자가 취소할 수 있다. 초기 엔진 Promise가 영원히 멈추는 경우 내부 Worker의 즉시 종료까지 보증하지 못한다. 저속망·실기기에서 별도 확인 필요.
- 원본 사진은 앱 서버로 전송하지 않는다. 네이버 후기 수집/자동 요약은 API로 제공 가능한 범위·약관을 확인한 뒤 설계해야 하며, 일반 검색 API가 전체 지도 후기를 제공한다고 가정하지 않는다.
